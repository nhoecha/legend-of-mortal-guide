# 활협전 도감 공략기 · 세이브 리더

활협전(Legend of Mortal)의 도감 세 권(생사부 · 한청서 · 풍운사)을 채우려고 만든 도구 모음이다. 게임 파일에서 조건을 직접 읽어 정리했다.

## 쓰기 전에

- **한 사람이 자기 플레이에 필요한 만큼만 고쳐 가며 만든 도구다.** 쓰기 불편할 수 있고, 판정과 조건에 오류가 있을 수 있다. 실제로 여러 번 틀렸다가 고쳤고, 아직 못 찾은 오류가 남아 있을 것이다.
- 기준 판은 `release_1.0.5000.13` 이다. 그 뒤의 패치와는 맞지 않을 수 있다.
- 세이브를 읽기만 하고 쓰지 않는다. 그래도 쓰기 전에 세이브 폴더를 백업해 두기를 권한다.
- 공략기와 위키에는 결말과 분기에 대한 스포일러가 그대로 들어 있다.
- 비공식 팬 제작물이고 게임 제작사와 관계가 없다. 권리자가 요청하면 내린다.
- 수정 요청은 받지 않는다. 자유롭게 포크해서 고쳐 쓰면 된다.

## 들어 있는 것

| 무엇 | 파일 | 하는 일 |
|---|---|---|
| 웹 공략기 | `활협전-도감.html` | 도감 목록 · 묶음 지도 · 런 플래너 · 이번 런 목표 · 사건 조건 · 시스템(위키) |
| 세이브 리더 | `도구/run.bat` → `save_read.py` | 지금 세이브의 상태와, 이번 회차에서 아직 딸 수 있는 도감 |
| 위키 | `위키/*.md` | 분기 · 심계 · 루트 · 세이브 구조에 대한 정리. 공략기의 「시스템」 탭과 같은 내용 |
| 판정 규칙 | `도구/판정-규칙.md` | 무엇을 가능/불가로 판정하는지와 그 이유 |

공략기의 런 플래너와 세이브 리더는 서로 다른 것을 센다. 플래너는 세이브와 무관하게 「도감 전체를 최소 몇 회차로 나눌 수 있나」를 보고, 리더는 「지금 이 회차에서 앞으로 무엇을 딸 수 있나」를 본다. 숫자가 다른 것이 정상이다.

공략기 도감 목록의 체크박스는 획득 표시가 아니라 「이번 회차에 볼 것」을 고르는 것이다. 고른 항목들의 조건이 「이번 런 목표」 탭에 합쳐져 나온다.

## 공략기만 쓰기

`활협전-도감.html` 을 받아 브라우저로 연다. 설치할 것이 없다.

공개본은 획득 표시를 전부 비워 두었다. 자기 세이브의 획득 여부를 넣으려면 아래 「직접 굽기」가 필요하다.

## 세이브 리더

파이썬 3 과 표준 라이브러리만 쓴다(3.12 에서 썼다). Windows 기준이다.

```
도구\run.bat                더블클릭. 세이브가 바뀔 때마다 다시 그린다
python save_read.py         한 번만 출력
python save_read.py --list  세이브 목록
python save_read.py --all   이 회차 갈래로는 못 따는 항목까지
python save_read.py --flags 유학   그 말이 든 플래그를 전부
```

세이브는 `%USERPROFILE%\AppData\LocalLow\Obb Studio\Mortal` 에서 찾는다. 보고서를 내는 데에는 게임 설치본이 필요 없다.

감시 중에 도감을 새로 따면 리더가 공략기를 다시 구우려 한다. 이 단계는 게임 설치본과 아래의 `lua/` 추출이 있어야 하고, 없으면 다시 굽기만 실패한다.

장면 요약 일부는 게임 대본에서 뽑은 파일(`summary.json`)을 쓴다. 대본은 저장소에 넣지 않았으므로 필요하면 아래 순서로 직접 만든다.

## 직접 굽기

게임 설치본이 필요하다. 설치 경로는 `도구/game.py`, `도구/extract_lua.py`, `도구/unity_de.py` 에 Steam 기본 경로로 적혀 있으니, 다른 곳에 설치했으면 세 곳을 고친다.

`도구/` 안에서 차례로 돌린다.

```
extract_lua.py    게임 → lua/          (게임 업데이트 때만)
build_graph.py    lua + 게임 → graph.json
mk_flagdep.py     lua + graph → flagdep.json, summary.json
build_site.py     graph + 세이브 → data.json
mk_events.py      사건 조건 글 → events.json
mk_prereq.py      선행 인물 → prereq.json
mk_forks.py       분기 트리 → forks.json, route_forks.json
mk_inherit.py     계승 → inherit.json
mk_wiki.py        위키/*.md → wiki.json
gen_html.py       전부 → 활협전-도감.html

mk_affect.py      lua + 게임 → affect.json, pos.json
mk_presence.py    lua + 게임 → presence.json
mk_story.py       lua → story.json
mk_savemap.py     게임 → savemap.json   (게임 업데이트 때만)
```

글만 고쳤으면 `mk_events.py` → `gen_html.py` 로 충분하다. `gen_html.py` 는 HTML 을 통째로 덮어쓴다.

## 알려 둘 한계

- 「막힌 항목」 판정의 일부는 작성자의 세이브에서 얻은 근거에 기대고 있다. 이미 딴 항목을 막는 것처럼 보이는 플래그를 엔진이 세우는 것으로 보고 걸러내는 식이다. 도감을 거의 못 딴 세이브로 `build_site.py` 를 다시 돌리면 이 근거가 줄어 판정이 달라질 수 있다.
- 미완성 채로 출시된 루트가 게임 파일에 남아 있어, 조건은 있는데 실제로는 갈 수 없는 항목이 있다. 찾은 것은 「달성 불가」로 표시했지만 전부라고 장담하지 못한다.
- 아직 확인하지 못한 것은 `위키/미확인-목록.md` 에 있다.

## 넣지 않은 것

- 게임 대본과 `lua/` 추출본, 도감 인물 소개 원문. 각자의 설치본에서 뽑아 쓴다.
- 커뮤니티 공략 시트. 초기에 대조용으로 썼지만 남이 만든 자료라 싣지 않았다. 시트와 다르게 판정한 곳은 「사건 조건」 탭에 이유와 함께 적어 두었다.
