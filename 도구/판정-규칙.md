# 판정 규칙과 도구 내부

세이브 리더와 공략기가 **무엇을 가능/불가로 판정하는지, 왜 그렇게 좁혔는지**를 적은 문서다. 쓰는 법은 저장소 맨 위 `README.md` 에 있다.

본문의 「핸드오프 N장」은 공개하지 않은 작업 로그를 가리킨다. `parsed.json` 은 커뮤니티 공략 시트를 옮긴 것이라 저장소에 넣지 않았다.

## 파이프라인

```
extract_lua.py → build_graph.py → mk_flagdep.py → build_site.py
  → mk_events.py → mk_prereq.py → mk_inherit.py → mk_forks.py → gen_html.py
mk_presence.py → mk_cast.py        (인물이 언제 오가고, 어느 장면에 나오는가)
mk_story.py                        (장면 안의 이야기 조각이 어느 가지에 있는가)
mk_intro.py                        (도감 인물 소개를 한 사람씩 읽는 ../활협전-인물소개.html. 파이프라인과 따로 돈다)
```

- `game.Game()` 로드는 약 52초 걸린다. `build_graph.py` 와 `build_site.py` 가 각각 부른다.
- `mk_flagdep.py` 가 `build_site.py` 보다 **먼저** 와야 한다. `build_site` 가 `flagdep.json` 의
  `misDead`(꺼진 미션 안에서만 세워지는 값)를 읽어 항목을 막는다.
- `gen_html.py` 는 `활협전-도감.html` 을 **덮어쓴다.** 돌리기 전에 백업할 것.
- 필요한 입력: `graph.json` `parsed.json` `data.json` `events.json` `prereq.json` `inherit.json` `forks.json` `bundles.json`

### `lua/` 에는 게임이 돌리는 판만 있다 (2026-09-29)

대본은 번체(`story/chinesetraditional`, 전체 1,802개)와 간체(`story/chinesesimplified`, 옛 판 477개) 두 벌이다.
`extract_lua.py` 가 `globalgamemanagers` 의 ResourceManager 컨테이너 경로로 둘을 가려 **번체만 `lua/`**,
간체는 `lua_legacy/` 에 둔다. 그래서 `lua/` 에는 `__<pathid>` 붙은 중복이 없다.

**왜**: 전에는 둘을 한 폴더에 넣고 스크립트마다 이름이 먼저 오는 쪽을 골랐다. 422쌍 중 204쌍이 간체 옛 판이었고,
옛 `back_001` 은 뒷산 업무가 `Back_02`(용상 도전)를 거치지 않아서 도구가 없는 「둘러보기」 버튼을 안내했다.
간체 판은 로직까지 다르므로 판정 근거로 쓰지 않는다. 원문 문구를 찾을 때만 `lua_legacy/` 를 본다.
`extract_lua.py` 는 두 폴더를 **지우고 다시 쓴다** — OneDrive 가 대량 삭제 알림을 띄울 수 있다.

### 업무·자유의 두 단계 표 (`then` · `forward`)

뒷산·대장간·외성은 행동을 누르면 `var2` 표(특수 사건)를 먼저 굴리고, 꽝(`SetNextScript(var1)` 만 하는 결과)이면
`var1` 표를 굴린다. `build_graph.py` 가 허브 대본에서 이 쌍을 읽어 `position[…].then`, 꽝 결과에 `forward: true` 를 싣는다.
`save_read.pos_elig` 가 두 확률을 곱하고 이름은 두 번째 표(`뒷산 · 업무`)를 쓴다. `build_site` 의 장소 이름도 같다.

## 장면 요약

`scene_ko.py` 의 `SCENE_KO` 가 손으로 쓴 요약 맵이다. `build_site.py` 가 `graph.json` 의 자동 요약(첫 대사 2줄) 위에 덮어쓴다. 새 요약을 추가할 자리는 거기다.

문체: `장소 · 등장인물 — 무슨 계기로 시작하는 장면인가`. **사건의 결과와 반전은 쓰지 않는다** (스포 방지).

## 세이브 읽기 도구 (save_read.py)

플레이 중인 회차의 상태를 읽어, 지금 어디에 있고 이 회차에서 아직 무엇을 딸 수 있는지 보여준다.

```
도구\run.bat                더블클릭. 세이브가 바뀔 때마다 자동으로 다시 그린다
python save_read.py         한 번만 출력
python save_read.py --list  세이브 목록
python save_read.py --all   이 회차 갈래로는 못 따는 항목까지
python save_read.py --flags 유학   그 말이 든 플래그를 전부
```

**세이브는 읽기만 한다.** 쓰지 않는다.

### 조건 대조

목록의 각 항목 아래에 그 경로가 요구하는 조건을 한 줄로 붙이고, **지금 세이브 값과 대조**한다.

```
생#103 꽃을 지키는 망자      2년차 10월 중순
       └ 행동력 ≤2 ✗4  처세 <40 ✗66  엽운상 호감도 ≥30 ✓   2개 모자람
```

- 못 맞춘 것을 앞에 놓는다. 다섯 개까지 보이고 나머지는 `+N`
- 부정 조건은 **혼자 있을 때만** 뒤집는다. 여러 비교가 한 덩어리로 부정된 것은 어느 쪽을 뒤집어야 하는지 알 수 없어 버린다
- 같은 스탯의 같은 방향 조건은 제일 빡센 것만 남긴다
- 이름으로 지금 값을 못 찾으면 `?` 로 두고 **맞았다고 하지 않는다**

수치 조건이 없으면 그 자리를 **방법**과 **플래그**로 채운다.

```
생#67 한을 품고 죽다     └ 전투에서 패배: 屠滅崆峒 決鬥金烏上人      수치 조건 없음
생#44 도주에 실패하고…   └ 구력 <50 ✓  주사위: 도주 실패 기준 <80   수치 조건 맞음
한#22 은원의 끝자락      └ 조건 없음 — 그 장면이 오면 발생          수치 조건 없음
```

**플래그에는 ✓/✗ 를 붙이지 않는다.** 플래그가 지금 0 인 것은 대개 「아직 안 왔다」이지
「못 한다」가 아니기 때문이다. 실제로 못 하는 경우는 갈래 판정이 따로 잡는다. 이벤트가
도는 동안에만 값이 있는 것(`범용`·`임시 플래그`)은 아예 버린다 — 세이브의 값으로 판정해도
의미가 없다.

### 심계는 한 회차에 한 명으로 본다

작성자의 방침이다. 「변심의 꿈」으로 갈아탈 수는 있지만 갈아타면 지금 심계로 열리는 쪽이 닫히므로,
**맞바꾸기**로 보고 「다른 심계라야 되는 것」에 따로 모은다. 그 아래에 **심계별로 몇 개가 열리는지**
표를 붙여, 무엇을 고르는 문제인지 한눈에 보이게 한다.

### 아직 안 정해진 분기를 「골랐다」고 읽지 않기

플래그 0 이 「그 값을 골랐다」인지 「아직 안 정했다」인지는 분기마다 다르다.
`sect` `snow` `league` `tourney` `banquet` `runaway` `qingcheng` 는 0 이 곧 미정이다.

**`study`(유학 선택)만 0 이 「당문 잔류」이기도 하다.** 그래서 시점을 함께 본다 —
회의(2년 2월 상순, wk 2021)가 오기 전이면 아직 안 정한 것이다. 이 처리를 빼먹으면
1년차 세이브에서 공동파 전용 항목이 전부 「불가」로 잘못 뜬다.

**부모 분기 검사에도 같은 판정을 써야 한다.** 한쪽만 고치면 자식 분기를 요구하는 항목이
여전히 막힌다 (심계 욱죽이 `sect` 를 요구하고 그 부모가 `study` 라서 그랬다).

### 이미 놓친 것 가려내기

세이브의 플래그가 조건과 다를 때, **아직 못 한 것**인지 **이제 못 하는 것**인지를 가른다.
「이제 못 한다」로 보는 근거는 둘뿐이다.

1. **인물 영입 창이 지났다** — `prereq.json` 의 인물별 창(`when`)과 지금 시점을 비교한다.
   창 표현에 `→` 나 `이후` 가 들어 있으면 **열려 있는 것이므로 마감으로 쓰지 않는다**
   (용상의 「1년 9월 상순 첫 만남 → 외성 회복 이후」를 1년 9월 마감으로 읽어 오탐이 났다).
2. **그 값을 세우는 곳이 전부 지나갔다** — `data.json` 의 `flagWhen`. **미션이 못박은 시점만**
   쓴다. 그래프의 `_earliest` 는 하한 추정이라 「마지막 기회」로 읽으면 **아직 오지도 않은
   사건을 지났다고 말한다** (공동 영전이 3년차인데 2년 10월로 잡혀 오탐이 났다).

둘 다 아니면 조용히 넘어간다. 못 한다고 단정하는 쪽이 훨씬 나쁜 오류다.

### 시점 추정은 챕터로 가둔다

챕터는 순서대로 흐르므로 **그 챕터가 시작하기 전에는 일어날 수 없다**. 그래프 하한만 쓰면
ch5 사건이 「2년차 10월 이후」로 보여 곧 올 것처럼 읽힌다. 챕터 범위와 교집합을 잡아
「3년차 3월 이후 ~ 3년차 5월 이전」처럼 적는다.

### 플래그는 「아직」과 「됨」으로만 나눈다

`아직 공동 영전 - 서행 참전` 처럼 아직 안 된 것을 앞에 놓고, 끝의 표시에 `플래그 N개 대기` 를
붙인다. **✗ 는 쓰지 않는다** — 대부분 「아직」이지 「못 한다」가 아니기 때문이다.

플래그를 세우는 조건은 **거슬러 올라가서** 판정한다. `mk_flagdep.py` 가 lua 의 if/elseif 를
따라가며 각 `SetFlag` 를 감싼 분기의 조건을 모아 `flagdep.json` 을 만들고, `save_read.py` 가
그것으로 **최소 고정점**을 돌린다.

- 순환(자기 값이 이미 있어야 자기 값을 만드는 꼴)은 **못 만드는 것**으로 본다
- lua 어디서도 세우지 않는 플래그는 `flagDefault` 의 기본값에서 움직이지 않는다
- 조건을 못 읽은 자리가 하나라도 있으면 **열어 둔다**. 「못 한다」고 잘못 말하는 쪽이 훨씬 나쁘다

이걸로 3단 사슬이 잡힌다. 「공동 영전 - 소사매 참전」은 `ch5_4_4` 가 세우는데 그 자리가
`M30026` 안에 있고 `M30026` 은 아무데서도 안 세워진다. 남은 길은 「엽운주 참전 == 1」을 거쳐
2 를 만든 뒤 1 로 바꾸는 것뿐인데, 엽운주가 떠났으면 그마저 막힌다.

**끝의 「수치 맞음」은 여전히 수치만 봤다는 뜻이다.** 「대기」 중인 플래그는 아직 안 온 것일 수도,
못 오는 것일 수도 있는데 후자는 위 판정이 따로 잡아 목록에서 뺀다.

끝의 표시는 **무엇을 판정했는지**를 말한다. 「수치 조건 맞음」은 수치만 봤다는 뜻이고,
플래그까지 다 됐다는 뜻이 아니다.

### 세이브 종류

게임의 「불러오기」 화면과 파일이 이렇게 대응한다.

| 화면 | 파일 | 루트 클래스 |
|---|---|---|
| 자동 저장 · 이야기 | `Save_auto.dat` | `AutoGameSave` (안에 `GameSave`) |
| 자동 저장 · 육성 | `Save_auto_free.dat` | 〃 |
| 자동 저장 · 전투 | `Save_auto_battle.dat` | 〃 |
| 수동 저장 NNN | `Save_NNN.dat` | **`GameSave` 가 곧 루트** |
| (도감 진행도) | `Save_universe.dat` | `UniverseSave` — 건너뛴다 |
| (열전 기록) | `Legend_NNN.dat` | `LegendSave` — 건너뛴다 |

**자동 저장과 수동 저장의 루트 모양이 다르다.** 자동은 껍데기가 하나 더 있고 수동은 없다.
둘 다 처리하지만, 새로운 모양이 또 나올 수 있으므로 `--watch` 는 못 읽는 파일을 만나면
그 파일을 건너뛰고 다음으로 넘어간다. **감시가 통째로 죽지 않는다.**

### 파일

- `nrbf.py` — .NET BinaryFormatter(MS-NRBF) 리더. 회차 세이브 `Save_*.dat` 가 이 형식이다.
  도감 진행도(`Save_universe`)만 게임이 JSON 으로도 써 주고 회차 상태는 이 이진 형식뿐이다.
- `mk_savemap.py` → `savemap.json` — 스탯·인물·플래그·심계 이름표. **게임을 여는 유일한 단계**라
  한 번만 돌리면 되고, 게임이 업데이트되면 다시 돌린다.
- `save_read.py` — 보고서 본체. 표준 라이브러리 + 위 두 개 + `data.json`/`forks.json`/`route_forks.json`.
  게임 설치본은 필요 없다.

`lover` 스탯의 값은 **0 소사매 / 1 서행 / 2 엽운상 / 3 우소매 / 4 상관형 / 5 하후란 / 7 위국 / 8 용상**.

## 위키 (위키/*.md → 「시스템」 탭)

게임 시스템에 대한 **현재 이해**를 주제별로 모은 곳. 핸드오프가 "언제 뭘 했나"라면 위키는
"지금 무엇이 사실인가"다. 29장까지 쌓인 핸드오프를 뒤지다 24장의 **틀린 문장에 스스로 속은 뒤**
만들었다.

```
위키/분기와-회차설계.md      유학·문파·가출·청성행·설산행, 판정 근거
위키/심계와-공략루트.md      둘의 차이, 변심의 꿈 트리, 막힌 루트
위키/게임파일과-세이브.md    무엇이 어디 있고 어떻게 읽는가, 파이프라인
위키/미확인-목록.md          모르는 것만. 여기 있는 건 단정 금지
```

`python mk_wiki.py` → `wiki.json` → `gen_html.py` 가 「시스템」 탭으로 렌더링한다.

### 쓰는 규칙

모든 주장에 **확신도와 근거**를 붙인다. 이게 이 위키의 존재 이유다.

- **확인됨** — 파일명·줄번호, 또는 작성자가 플레이로 확인. 근거 없으면 확인됨이라고 쓰지 않는다
- **추정** — 왜 그렇게 보는지와 **무엇으로 반증되는지**를 같이 적는다
- **미확인** — 모른다고 적고 `미확인-목록.md` 에 모은다

새로 알게 되면 해당 페이지로 옮기고 미확인 목록에서 지운다. **틀린 것으로 밝혀지면 되돌려 놓는다** —
미확인 목록 아래쪽에 「해결된 것」으로 남겨서 같은 착각을 반복하지 않게 한다.

문법은 제목·문단·목록·표·펜스 코드블록·인용과 인라인 굵게/코드/`[[페이지이름]]` 링크뿐이다.

## 상류 조건 (upReqs) — 두 가지를 걸러낸다

`build_site.py` 의 `upstream_pairs()` 가 「그 장면까지 오는 길에 걸려 있던 조건」을 모은다.
여기서 두 번 좁혔다. 둘 다 **없는 조건을 만들어 내서** 멀쩡한 항목을 불가로 만들었기 때문이다.

### 1. 순서형 스위치의 형제 조건은 버린다 (2026-09-07)

`checkpointmanager.Switch` 는 갈래가 아니라 **순서**다. 위에서부터 먼저 맞는 하나가 잡히고,
마지막 가지는 else 라서 **대응하는 조건 문장이 아예 없다.** 그래서 그 길로 온 경우에는
아무것도 안 실리는데, 형제 가지의 조건은 그대로 남아 필수처럼 보인다.

한#49 「상갓집 개」가 그랬다.

```
Ch_8_3_2_1_5_002    1: 단합 <50 → ch8_3_1_1_3     (ch8_4_1_1 로 빠진다)
                    2: 단합 <80 → ch8_3_1_1_2  ┐
                    3: (그 외)  → ch8_3_1_1_1  ┴ 둘 다 ch8_3_1_2 로 합류한다
```

3번 가지에는 문장이 없어 「단합 <80」만 남았고, 단합 98 인 회차에서 **넘쳐서 못 딴다**고
나왔다. 실제로는 둘 다 같은 곳으로 가므로 조건이 아니다. 그래서 **마지막 가지로도 올 수
있는 스위치는 그 스위치가 실은 문장을 전부 뺀다.** 53개 조건 중 40개가 이때 빠졌는데,
빠진 것들은 대부분 애초에 성립할 수 없는 조합이었다 (`구력 <50` 과 `구력 <60` 동시 요구 등).

**경로별 교집합(모든 길에 공통인 것만)도 시도했지만 버렸다.** 자유행동 허브에서 조건 없이
들어오는 길이 하나라도 있으면 상류가 통째로 날아가, 24개 항목의 조건이 전부 비었다.
결과는 같으면서 영향 범위가 절반인 쪽을 골랐다.

### 2. 이미 지나간 자리의 조건은 대조하지 않는다 (2026-09-07, 작성자 제안)

조건마다 그것을 읽는 장면(`at`)과 그 장면의 시점(`atWk`)을 함께 싣는다. `save_read.py` 의
`passed()` 가 세이브의 현재 시점과 견주어, 이미 지난 자리의 조건은 **판정에서 빼고** 맨 뒤에
`지남` 으로 흐리게만 남긴다.

지난 자리의 조건은 그때 값으로 이미 판가름났다. 생#61 의 `도덕 >=60` 은 1년차 8월
(`S0103_01`) 자리인데 4년차 값을 대고 있었다. 맞든 틀리든 답은 이미 정해져 있어서,
지금 값으로 따지면 틀린 말을 한다.

`atWk` 는 순(旬) 없이 그 달 기준이라, **같은 달이면 아직 안 지난 것으로 본다.**
장을 못 읽는 자리(자유행동·사이드 스토리)는 `atWk` 가 없고, 그때는 지나갔다고 단정하지
않는다 — 계속 대조한다.

### 웹 플래너와 갈라지는 곳

`gen_html.py` 도 같은 `upReqs` 를 읽으므로 1번은 양쪽에 함께 적용된다. **2번은 리더에만
있다.** 런 플래너는 회차를 처음부터 계획하는 관점이라 현재 시점이 없고, 그쪽에서는 모든
조건이 아직 오지 않은 것이 맞다. 판정이 갈라진 것이 아니라 보는 시점이 다르다.

## 웹 공략기가 이 회차를 안다 (2026-09-07)

브라우저는 `file://` 에서 세이브 파일을 읽지 못한다. 그래서 **구울 때 심는다.**

```
save_read.verdicts()      항목마다 가능/심계/지남/불가 를 계산한다. 그리기는 하지 않는다
save_read.save_verdicts() 그 결과를 웹이 쓸 모양(JSON)으로. 세이브가 없으면 None
gen_html.py               위를 불러 <script id="rundata"> 에 박는다
```

**계산과 렌더링을 갈라 둔 이유**는 지침의 「세이브 리더와 웹 플래너가 같은 판정을 쓰는지
확인한다」다. 판정 코드를 복사하면 반드시 갈라지고, 그때부터 둘이 같은 항목을 두고 다른
말을 한다. `library_section()` 은 이제 `verdicts()` 의 결과를 그리기만 한다.

웹에 생기는 것: 카드마다 회차 배지(`이번 회차 가능` / `시점 지남` / `이 회차 갈래로는 불가`
/ `심계를 바꿔야`), 상단 요약의 세이브 줄, 상태 필터의 「이번 회차에 가능」 버튼. 세이브가
없으면 `RUN` 이 `null` 이라 배지도 버튼도 나오지 않고 공략기는 그대로 동작한다.

### 다시 굽는 두 갈래

감시 루프(`--watch`)가 두 가지를 구분한다. **재는 대상이 다르면 비용도 다르다.**

```
도감(Save_universe.json) 이 바뀜   rebuild_guide(full=True)    build_site + gen_html   74초
세이브(.dat) 가 바뀜               rebuild_guide(full=False)   gen_html 만              1.1초
```

`data.json` 은 세이브와 무관하므로 세이브만 바뀌었을 때 `build_site.py` 를 돌릴 이유가
없다. 측정값이다 — 74초를 1.1초로 줄였고, 그래서 한 순 넘길 때마다 갱신해도 부담이 없다.

**`run.bat` 이 이미 돌고 있다면 코드를 고쳐도 반영되지 않는다.** 창을 닫고 다시 켜야 한다.

## 쌓이는 값 추적 (누적 연단 등, 2026-09-07)

`누적 연단` `누적 무학` `누적 단조` `누적 공헌` `요리` 는 **게임 UI 에 안 뜨는 내부 스탯**이다.
로컬라이제이션에 `PlayerStat/*` 이름이 없어서 `savemap.json` 에 안 실렸고, 그래서 리더가
`누적 연단 >=250 ?` 처럼 물음표로 두고 판정을 못 했다 — 생#39·한#9·한#10·한#11 이 그랬다.

세이브에는 처음부터 들어 있었다. `mk_savemap.py` 의 `EXTRA_STATS` 로 손수 이름을 붙인다.

```
total-poison-point    누적 연단      全毒藥點數
total-martial-point   누적 무학      全武學點數
total-weapon-point    누적 단조      全鍛造點數
total-contribution    누적 공헌      全貢獻度
faction-contribution  문파 공헌      門派貢獻
cook                  요리
```

**이름은 `cond.py` 의 `STAT_KO` 와 정확히 같아야 한다.** `cur_value()` 가 조건문에 적힌
이름으로 `savemap['stats']` 를 역으로 찾기 때문에, 한 글자만 달라도 다시 물음표가 된다.

`track_stats()` 가 현재값과 문턱을 모은다. 문턱은 두 갈래로 센다 — `marks` 는 조건문 전체
(`graph.json` 의 switch)에서 모은 것이고, `lib` 는 그중 **아직 못 딴 도감**이 요구하는 값이다.
도감만 세면 누적 연단이 250 하나뿐이라 「지금 얼마나 왔나」를 알 수 없다. 리더의 스탯 칸과
웹 공략기 상단에 같은 값이 나온다.

### 소지품과 재능도 읽는다

`기술 …` `비급 …` `비급 등급 …` `잡물 …` `귀중품 …` 은 `Stats` 가 아니라 저마다 다른
목록에 있고, 세는 칸도 다르다. `item_value()` 가 그것을 맡는다.

```
기술 X        Talents        Level          제일 높은 것
비급 X        Books          Count          합
비급 등급 X    Books          MartialLevel   제일 높은 것
잡물 X        Miscs          Count          합
귀중품 X       SpecialItems   Count          합
```

**「비급 등급 」을 「비급 」보다 먼저 걸러야 한다** — 접두사가 겹쳐서 순서가 뒤바뀌면
등급 조건이 개수 조건으로 읽힌다.

**안 가진 것과 못 읽는 것을 섞지 않는다.** 목록에 없으면 `0` 이고, 이름 자체를 모를 때만
`None` 이다. 둘을 섞으면 「안 가졌다」가 「우리가 못 읽었다」로 보여 조건이 조용히 통과한다.

이걸 붙이자 새 회차에서 「조건을 다 읽었고 다 맞는 것」이 0 → 6 으로 늘었다. 못 읽던
조건이 판정에 들어온 것이지, 판정이 느슨해진 것이 아니다.


## 장면에 나오는 사람도 조건이다 (2026-09-07)

조건문에 절대 안 적히는 요구가 하나 있다 — **그 인물이 이 회차에 있어야 한다.**

생#98 「패자의 죽음」이 그랬다. 조건은 `결투 승패 == 0` 하나뿐이라 도구가 **확실**이라고
불렀는데, 그 장면에는 엽운상이 나온다. 엽운상을 아직 거두지 않은 회차에서는 열릴 수 없는
자리다. 작성자가 잡아 주었다 — 「없는 인물이 있는데 확실로 뜨면 안 되지」.

`mk_cast.py` 가 장면마다 누가 나오는지를 `cast.json` 으로 낸다. `enclosing()` 으로 **조건
없이 나오는 사람(sure)** 과 **조건부로만 나오는 사람(maybe)** 을 갈라 둔다.

`save_read.cast_missing()` 이 판정에 쓴다. 세 가지를 좁혀 두었다.

- **`sure` 만 센다.** 조건부로 나오는 사람은 없어도 그 장면은 열린다. `maybe` 까지 세면
  생#68 하나에 다섯 명이 붙어 멀쩡한 항목이 전부 「대기」가 된다.
- **엔딩과 업적은 보지 않는다.** 그때 살아 있는 사람을 전부 부르는 장면이라, 특정 인물이
  조건인 것이 아니라 결과를 함께 보여 주는 것이다. 풍#13·15·19 가 다섯 명씩 달고 있었다.
- **들어오는 길이 여럿인 `entries` 는 보지 않는다.** 그 길 중 하나만 타면 되기 때문이다.
  보는 것은 그 장면 자신과 `origin.via` 뿐이다.

**「불가」로 내리지 않고 「대기」까지만 내린다.** 아직 거둘 수 있는 인물이면 조건은 채워질
수 있고, 영입 창이 지난 경우는 기존 `presence_deadline` 이 이미 「이 회차 불가」로 잡는다.
지금 회차 기준 17개 항목이 이 규칙에 걸린다.

**남은 거친 자리**: 당문 대난투 계열(생#68·84·90)은 네 명씩 달고 나온다. 그 장면들이
실제로 여러 사람을 조건 없이 부르기 때문인데, 그중 몇이 진짜 필수인지는 확인하지 않았다.

## 값 0 이 「아직」인가 「안 함」인가

`유학 선택(M20008)` 이 0 이면 도구가 「유학 안 감 · 당문 잔류」라고 단정하고 있었다.
새 회차 1년차인데도 그렇게 나와서 작성자가 이상하다고 했다.

`meeting_option_01` 을 읽어 보니 **M20008 에 1 이나 2 만 쓴다.** 「유학 안 감」을 골라도
0 을 쓰지 않고 그냥 안 건드린다 — 게임이 미정과 안 감을 구분하지 않는다.

**그렇다고 `UNDECIDED` 에 넣으면 안 된다.** 한 번 그렇게 고쳤다가 되돌렸다. 회의
시점(2년차 2월 상순, `STUDY_WK`)이 지나면 0 은 「안 감」으로 굳는데, `UNDECIDED` 는
시점을 안 보므로 회의를 지나고도 영영 「아직 안 정해짐」이 된다. `make_decided()` 에
이미 그 시점 규칙이 있었고, 화면도 같은 `decided()` 를 쓰게 맞췄다.

시점이 확인된 갈래는 `mk_forks.py` 의 `when` 에 적는다. 화면은 확인값이면 그대로,
추정이면 「무렵」을 붙여 둘을 구분한다.

```
유학 선택    아직 안 정해짐 (값 0) · 지금은 유학 안 감 · 당문 잔류
             · 공동파 유학   23개 (수치 무시하면 28)
```

덤으로 갈래별 개수 비교가 붙는다. 유학처럼 되돌릴 수 없는 갈래에서는 그 숫자가 결정
근거다.

## 갈래가 언제 정해지는가

「이 회차의 갈래」 줄 끝에 시점이 붙는다. **하한 추정이라 「무렵」을 붙여 적는다.**

```
유학 선택       아직 안 정해짐 (값 0) · 지금은 유학 안 감 · 당문 잔류   1년차 8월 ~ 2년차 8월 무렵
가출 경로       아직 안 정해짐 (값 0)                                 2년차 6월 무렵
너의 결정       아직 안 정해짐 (값 0)                                 3년차 11월 무렵
```

값은 `flagWhen[플래그].estMin/estMax` 다. `build_site.py` 가 그 플래그를 세우는 모든
스크립트에 `_at_wk()` 를 걸어 모은 것으로, **미션이 못박은 시점(`set[값].min/max`)과는
다른 칸이다.** 판정에는 여전히 못박힌 시점만 쓴다 — 추정을 「마지막 기회」로 읽으면 아직
오지도 않은 사건을 지났다고 말하게 된다.

**추정이 실제보다 이른 경우가 있다.** 회의처럼 여러 자리가 같은 스크립트를 공유하면 그중
가장 이른 자리가 하한이 된다. 유학 선택이 「1년차 8월 ~ 2년차 8월」로 넓게 잡히는 것이
그 예다 — 실제 회의는 그 창 안 어딘가다. 확인된 것은 「너의 결정 3년차 11월」로,
`ch7_4_2_break_start_01` 과 맞는다.

「청성행」은 우리가 붙인 갈래라 실제 플래그가 없어 `flagWhen` 으로 못 잡는다.
`mk_forks.py` 의 `when` 필드에 손으로 적는다 (갈리는 자리 `ch2_4_9_2` = 2년차 8월).

## 갈래 요구는 조건문에 안 적힌다

생#98 「패자의 죽음」은 조건이 `결투 승패 == 0` 하나뿐이라 「조건 없음 — 그 장면이 오면
발생」으로 보였다. 작성자가 「저번 런에 아예 안 떴다」고 알려 주어 파 보니, 그 항목의 장면
`ch3_1_7_5_1` 은 **청성 유학 5부작(M2011_01~05)** 안에 있었다. 전투도
`CL_1327_01 逃離青城 唐門弟子` 다.

`build_site.py` 의 `QC_PREFIX` 가 이미 `ch3_1_` 를 청성 라인으로 잡아 `o['qc'] = '1'` 을
싣고 있었고, `opt_verdict` 도 그것을 판정에 쓰고 있었다. **빠진 것은 화면이었다** — 갈래를
타야 한다는 말이 어디에도 안 나왔다. `need_line()` 이 그 줄을 만든다.

```
생#98  패자의 죽음   2년차 8월 이후 ~ 2년차 11월 이전   대기
       ↳ 산길 · 조활, 엽운상, 당방 — 호송 중에 앞길이 막힌다 · 그 장면의 전투에서 패배
       ↳ 갈래 청성행: 청성파 유학(가출 후)
       └ 조건 없음 — 그 장면이 오면 발생   수치 조건 없음
```

아직 그 갈래로 서 있지 않으면 `tier` 를 「확실」에서 내린다. 조건이 다 맞아도 갈래를 먼저
타야 그 장면이 오기 때문이다.

**갈래가 심계를 요구하는 경우도 잇는다.** 청성행은 `ch2_4_9_2` 에서 「마음에 둔 사람 ==
엽운상」일 때만 갈린다. 항목 자체에는 심계 조건이 없어서, 소사매 회차에서도 생#98 이
「가능」으로 보였다. `opt_verdict` 가 요구 갈래의 `needLover` 까지 따라간다.

**이미 그 갈래로 들어섰으면 묻지 않는다 (2026-10-07).** 청성행을 탄 뒤 변심으로 소사매로 갈아탄 세이브에서 생#42 가 「심계가 엽운상이어야 한다」로 떴다(작성자 제보). 그 요구는 갈림 자리(2년 8월)의 것이라 지나고 나면 뜻이 없다. `opt_verdict` 가 `decided(k)` 인 갈래는 `needLover` 를 건너뛴다. 세이브 넷으로 앞뒤를 견줬고 바뀐 것은 그 세이브의 세 항목뿐이다.

## 심계가 아직 없는 상태 (lover = 99)

「변심의 꿈」으로 비운 직후 세이브에는 `lover = 99` 가 들어 있다 — 심계 표에 없는 값이다.
그대로 다루면 「심계가 엽운상 여야 한다 (지금 99)」 같은 말이 나오고, 아직 아무 쪽도
안 닫혔는데 심계 조건이 붙은 항목이 전부 「심계를 바꿔야」로 빠진다.

`lover_of(run)` 이 표에 없는 값을 `None` 으로 돌려준다. 그러면 심계 판정 자체를 건너뛰고
(아직 고를 수 있으므로 옳다), 화면에는 「아직 정해지지 않음」으로 나온다.

## 그 장면 안에서 정해지는 플래그 (임시 플래그)

풍#20 「악은 악으로」의 조건은 `[임시 플래그 2] == 2` 하나뿐이라 「조건 없음 — 그 장면이
오면 발생」으로 보였다. 작성자가 「특정 인물 루트를 타야 하는 걸로 아는데, 엽운상이었던 것
같다」고 짚어 주어 파 보니 맞았다.

`A00002` 는 `ch6_8_4` 안에서 0 으로 깔린 뒤 선택지에 따라 1·2·3 이 된다. 값 2 는 두
번째 선택지이고, 그 선택지는 이렇게 잠겨 있다.

```lua
option_001[2] = Ch_6_8_4_002 and "O_6_8_4_003" or "~O_6_8_4_004"   -- ~ 가 잠김 표시
```

`Ch_6_8_4_002` = `[위국 공략 중] == 1 또는 [엽운상 무림대회 동행] == 1`.

**택일 조건이라 `mk_flagdep.py` 의 `reqs_of()` 가 버리고 있었다.** 못 박지 않는 것은
맞지만, 통째로 버리면 「조건 없음」이 된다. 이제 버리는 대신 문장을 `why` 로 실어 둔다.

`save_read.temp_flag_why()` 가 그것을 읽어 조건줄에 적고, **그런 항목을 「확실」이라고
부르지 않는다**(「미확인」으로 내린다). 값으로 대조하지는 않는다 — 택일이라 어느 쪽이
참인지 우리가 못 정하기 때문이다.

같은 자리인지 판단할 때 `scene_group()` 을 쓰면 안 된다. 그 함수는 `ch6_8_4` 처럼 마디가
짧은 이름에 `None` 을 준다(다른 용도로 만든 것이다). 여기서는 같은 스크립트이거나 한쪽이
다른 쪽의 앞자락일 때만 같은 자리로 본다.


## 자유행동 자리로 가는 길에 잠금이 있다 (pos_gate)

자유행동 항목의 조건을 볼 때, **그 자리에 갈 수 있는지**를 따로 봐야 한다. 잠금은 자리의
결과 스크립트가 아니라 **이동 메뉴**에 있다.

```lua
-- section_01_free_start_02.lua (공동파 지도)
sectionFree01[5] = Section_01_Free_Option_002 and "move+夺魄森林+1+0" or "~x"
```

`Section_01_Free_Option_002` = `[하후란을 스승으로 모심] == 1`. 그래서 한#23 은
탈백문 회차 전용이다. 항목 쪽 조건문에는 그런 말이 한 마디도 없다.

`linear_texts` 는 부모가 하나뿐인 동안만 올라가는데 `talk_girl5_02` 는 부모가 둘이라
첫 걸음에서 멈춘다. 그래서 `Position("X")` 를 부르는 lua 파일을 찾아 두고(`POS_CALLER`),
자유행동 origin 이면 거기서부터 다시 훑는다(`pos_gate`). 찻집(`Facility_002`)과
온천(`Facility_004`)도 같은 모양이었다.

**`linear_texts` 는 이제 잠긴 선택지(`Choice` 의 6번째 칸)의 조건도 읽는다.** 들어오는
길이 하나뿐인 동안만 훑으므로 그 잠금은 반드시 거치는 조건이다.

## 플래그 비교의 `>=`

`RE_FLAGCHUNK` 는 오래 `== N` 만 잡았다. 조건문의 플래그 비교 중 139개가 `>=` 인데
통째로 버려지고 있었다 — 시설 건설, 누적 횟수 카운터, 문파 호감도 같은 것들이다.
이제 `==` 와 `>=` 를 받는다.

읽는 쪽(`save_read.RE_FLAGCMP`, `gen_html`)도 연산자를 함께 뽑고, `flag_met()` 로
비교한다. **`>=` 는 불가 판정에 쓰지 않는다** — 누적값이라 그 값을 세우는 자리를 값으로
찾을 수 없다. 요구사항으로 적기만 한다.

## talk_ 스크립트 이름의 번호는 인물 번호가 아니다

`talk_girl5_*` 는 열아홉 편 중 열여덟에 **하후란**이 나온다(우소매는 한 번도 안 나온다).
`talk_girl4` 는 상관형이다. `talk_girl2`·`talk_special3` 은 그런 스크립트가 없다.
인물을 알고 싶으면 `cast.json` 을 세는 것이 맞다. 이름으로 짐작하면 안 된다.


## 세이브의 StorySave — 「지금 값」이 아니라 「그때 지나온 가지」

플래그는 결과만 말한다. 값이 지금 조건에 맞아도 **판정 순간에 맞았는지는 말해 주지 않는다.**
대사형 완쾌가 그랬다. 3년 1월 상순 `S0401_01` 은 처세 60 미만을 요구하는데, 작성자의 세이브는
그 자리를 지난 뒤 처세가 58 이었다. 네 조건이 전부 ✓ 로 찍혀 「성공」으로 읽힐 상황이었다.

`StorySave` 가 그것을 잡는다. 지나온 이야기 조각(`statmodifymanager.AddStory`)이 키로 남는다.

```
S0401_01_002  ●   처세 < 80 · 대사형 호감도 >= 40 은 통과했다
S0401_01_003  ●   처세가 60 이상이라 그 앞에서 갈라졌다   ← 여기로 갔다
S0401_01_004  ○   완쾌 가지
S0401_01_005  ○   의술·누적 연단 부족 가지
```

`mk_story.py` 가 lua 전체에서 조각을 걷어 `story.json`(조각 4520 개 / 장면 901 개)으로 낸다.
각 조각에 그것을 감싼 가지 조건이 붙는다. 리더에서:

```
python save_read.py --story S0401_01
```

**항목 판정에 전면 적용하지는 않았다.** 세 가지로 재 봤는데 잡히는 것이 없었다.

- 미획득 항목의 **장면 자체**를 지난 경우: 0 (지났으면 이미 땄다)
- 항목 경로의 조각 키가 「지난 장면인데 안 지난 가지」인 경우: 0
- 플래그를 세우는 자리를 지난 경우: 11 건이지만 **전부 오탐**이다 — 임시·범용 플래그는
  장면마다 다시 쓰이고, 인물 플래그는 「얻었다가 잃은」 것이라 세터를 지난 것이 곧
  「이제 못 한다」가 아니다.

그러니 쓸모는 **손으로 짚은 관문**에 있다. `save_read.ONESHOT` 의 `story` 항목이 그 자리다.
새 관문을 만나면 `--story <장면>` 으로 가지를 확인하고 그 표에 적는다.

## 플래그를 세우는 자리에는 미션 관문이 있다 (2026-09-12)

`mk_flagdep.py` 는 원래 lua 의 `if`/`elseif` 만 봤다. 그래서 **그 장면이 애초에 열리는가**가
판정에서 빠져 있었다. 「엽운상 공략 중」(G11002)이 그 구멍에 그대로 걸렸다 — 세우는 자리는
`S0208_05_05` 하나뿐이고 그 안에는 조건이 없어서, 어느 회차에서든 「아직 안 왔다」로 보였다.
실제로는 그 자리를 여는 미션 `S0208_01` 이 `_active: False` 다. ~~이 빌드에서는 아무도 못 세운다.~~

> **2026-09-30 정정 — 이 결론은 틀렸다.** 미션은 꺼져 있지만 5장(`ch5_4_1` · `ch5_4_2`)이 `SetNextScript("S0208_01")` 로 그 장면을 직접 부른다. 미션에서 추적을 멈춘 탓에 열려 있는 루트를 막았다(한청서 38 · 풍운사 19 · 생사부 105). `mission_gate` 는 이제 **꺼진 미션인데 다른 대본이 직접 부르는 장면**을 관문으로 치지 않고 그 부모로 더 올라간다. 살아 있는 미션은 예전대로 거기서 멈춘다. 맨 끝 절 참조.

`mission_gate(sc)` 가 그래프를 위로 훑어 그 장면을 여는 미션들을 찾고, 세 가지를 붙인다.

```
misDead   미션이 전부 꺼져 있다        → 이 빌드에서 못 만드는 값
misMax    미션에 적힌 마감             → 그 순을 넘기면 그 자리는 못 쓴다
need      미션 조건의 플래그           → 기존 need 와 합친다
```

### 갈림이 있어도 위로 다 훑는다

전에 쓰던 외길 추적(부모가 하나일 때만 올라감)으로는 들어오는 길이 여럿인 자리에서
미션에 닿지 못했다. `S0208_05_05` 가 그랬다. `mk_presence.mission_of` 와 같은 방식으로
BFS 로 올라가되, 부모에 `[자유행동]` 이 있으면 **관문을 아예 걸지 않는다** — 자유행동에서
바로 들어가는 장면은 미션이 안 열어도 나기 때문이다(용상 영입 `S0023_01_01`).

### `alts` 를 같이 읽지 않으면 정반대로 막는다

미션 조건을 읽을 때 **`alts` 를 반드시 같이 본다.** 이걸로 두 번 틀렸다.

```
ch7_5_6_1   conds [항전 노선 == 1]
            alts  M6003_04 西武林盟 決戰前夜  (conds 없음)
S0021_01    conds [용상 호감도 60 · 고백 · 항전 노선]
            alts  S0021_01_02_01 東西武林盟  [용상 호감도 60 · 고백 · 너의 결정 == 4]
```

main 만 읽으면 둘 다 「항전 노선 전용」으로 보인다. 그 상태로 판정에 넣었더니 서무림맹
회차에서 생사부 82(수라장)를 잘못 닫았고, 용상 루트를 **틀린 이유로** 막았다. 그래서:

- `misDead` 는 main 과 alts 가 **전부** 꺼져 있을 때만
- 미션 조건을 `need` 로 못 박는 것은 **alts 가 없을 때만**
- `misMax` 는 main·alts 전부에 마감이 적혀 있을 때 그중 **가장 늦은** 것

### 읽어 낸 조건을 못 읽은 조건보다 먼저 본다

`make_reachable._go` 는 `unknown` 인 자리를 만나면 그 자리를 곧장 「열려 있다」로 봤다.
그러면 같은 자리에 **읽어 낸** `need` 가 달려 있어도 통째로 무시된다. 순서를 뒤집었다 —
`need` 가 이미 막혔으면 그 자리는 못 쓰고, 통과했을 때만 `unknown` 으로 열어 둔다.

### 득표로 갈리는 자리는 lua 로 안 잡힌다 (DECIDED_ROUTE)

「항전 노선」(M70052)은 `ch7_4_3_2` 가 세우는데, 거기로 가는 갈림이
`Ch_7_4_3_1_002` = 「끝까지 싸운다 득표 1위」다. 득표 비교는 플래그 조건이 아니라서
`reqs_of` 가 못 박지 못한다. 회의 결과는 `M70015`(너의 결정)에 남으므로, 그 값이 굳었으면
다른 노선의 플래그는 그 회차에서 안 선다 — `save_read.DECIDED_ROUTE` 한 줄이 그것이다.

### 웹 공략기도 같은 것을 안다

`build_site.py` 가 `flagdep.json` 의 `misDead` 를 읽어 `DEAD_SET` 을 만들고, `_reach` 가
그 값을 False 로 본다. (한청서 38 · 풍운사 19 를 이것으로 막았던 것은 위 정정대로 풀었다.)
**`mk_flagdep.py` 를 `build_site.py` 보다 먼저 돌려야 한다.**

`wkMax` 는 순이 없으면 `stage 0` 으로 들어간다. 「4년차 3월 무렵」이 `4030` 이라, 그대로

## 판정을 내리기 전에 확인할 세 가지 (2026-09-29)

이번 세션에 틀린 판정이 거의 다 같은 이유였다. 스위치와 플래그만 보고 결론을 냈다.

1. **선택지 잠금을 본다.** `talk[N] = XXX and …` 처럼 정의 없는 조건으로 영구히 잠긴 선택지가 44 개 파일에 있다. 금향궁 방문이 그래서 강제다. `build_site.RE_DEADXXX` 가 이제 이것을 DEAD_OPT 에 넣는다.
2. **대본 텍스트를 읽는다.** 「공력을 거두지 않는다」는 감점·전투가 없어 안전해 보였지만 대사형이 검에 찔려 죽는 가지였다. `砍人_001` 같은 사운드와 `GetStoryText` 키를 `game.Game().t('Story/…')` 로 읽어 확인한다.
3. **세이브의 0 을 결정으로 읽지 않는다.** 0 은 「안 함」이자 「아직 안 정함」이다. 그 값을 세우는 장면의 시점이 지났는지 먼저 본다(`jhg_state` 가 그 예).

새로 생긴 표와 함수는 핸드오프 38장 「도구에 들어간 것」에 모아 두었다: `BRANCHED` 새 관문 셋, `jhg_state`, `CAST_NOT_GATE`, `SHEET_WRONG`, `CONFIRMED_BLOCK`, `NOT_BRANCH`(비움), 위키 `성정-내리기.md`.

## 못 서는 고리 · 막힌 경로 · 플래그가 품은 갈래 (2026-09-30)

생#42 「상갓집 개의 말로」를 작성자가 「청성 유학 회차여야 하지 않냐」고 물어 드러난 세 가지.

1. **스스로를 전제로 하는 setter.** 공동 영전 서행 참전(`M50010`)은 `M30026 == 1`(세우는 곳 없음) 이나 `M50010 == 2`(그건 `M50010 == 1` 이 전제) 뒤에서만 1 이 된다. `build_site.py` 가 기본값에서 출발해 전제가 다 서는 setter 만 받아들이는 고정점을 돌려 `UNSAT` 을 만든다. 못 읽은 조건이 있는 setter(`unknown`)는 열린 것으로 본다. 상관형 공략 중 2 도 같은 고리다.

3. **플래그가 품은 갈래·심계 (`FLAG_IMPLIES`).** 조건문엔 「엽운주 참전 == 1」만 적혀 있지만, 엽운주는 3년 1월에 떠나고 청성 회차만 붙잡으므로 그 경로는 `qc = '1'`. 「소사매 참전 == 1」은 3년 3월 그 순간 심계 소사매가 필요한데, 청성행은 심계 엽운상을 요구하므로 **`reqs` 에 넣지 않고 `loverLater` 글로만** 싣는다 — 넣으면 플래너가 두 심계를 상충으로 읽어 불가라 한다(변심의 꿈으로 된다). 리더 `need_line` 과 공략기 경로 줄이 그 글을 보여 준다.

## 「공략 중」이 켜지면 다른 사람의 결말은 닫힌다 (`save_read.route_closed`, 2026-09-30)

하후란 공략 중이 켜진 세이브에서 리더가 용상 결말(한#44 · 풍#15)과 소사매 결말(한#37 · 풍#14)을 「가능」으로 보여 주고 있었다. 예전 규칙(`route_outranked`)은 ch8_8_* 한 장면만 봤고, 「그 값에서 못 벗어나는가」를 `run.script` 의 장 번호로 재서 자유행동 세이브에서는 아예 돌지 않았다.

지금 규칙은 넷이고, 경로가 `req`(= `[X 공략 중] == 1`)를 가질 때만 본다.

1. X 의 값이 2 면 불가 — 수라장으로 끝났다.
2. X 가 소사매이고 값이 1 이 아닌데 3년차 5월 상순을 넘겼으면 불가. 켜는 자리(`ch5_5_1`)는 5장 공동 영전 사슬(`M4002_02`, 조건 없는 강제 미션) 안에만 있다.
3. 경로가 ch8_* 이고 X 가 용상·하후란인데 다른 사람이 1 이면 불가. 둘이면 `ch7_5_6_2` 가 수라장을 켜고 `ch7_5_6_3_2` 가 용상·하후란을 2 로 만든다. ch7_* 경로(생#82)는 수라장 자체가 목적이라 건드리지 않는다.
4. 결말 장면(`ch8_8_*` · `ch8_6_3_2` · `ch7_5_2_9`)은 첫 일치 하나만 잡으므로, 순서에서 앞선 사람이 1 이면 불가.

**좁힌 것.** 하후란을 놓친 회차(3년 7월 설산행 결승일을 지났는데 0)는 이 규칙이 잡지 않는다 — 그 날짜가 고정인지 확인하지 않았다. 용상의 마감은 기존 `missed_flags` 가 본다. 웹 공략기는 `save_verdicts` 로 같은 판정을 받는다.

## 선택지 잠금과 진입로를 플래그 조건으로 싣는다 (`mk_flagdep`, 2026-10-02)

`flagdep.json` 의 「이 값을 세우는 자리에 닿으려면 무엇이 필요한가」에 두 가지가 빠져 있었다.

1. **잠긴 선택지의 가지.** `enclosing(path, gates=True)` 가 `X = Condition("X")` → `arr[n] = X and "…" or "~…"` → `choose(arr)` → `if choice == n` 을 따라가, 그 가지 안의 `SetFlag` 에 잠금 조건을 붙인다. 읽어 낸 것은 `need` 로, 원문은 `gate` 로 싣는다. 택일 · 부정이 섞이면 `unknown` 으로 열어 둔다(스위치와 같은 규칙).
2. **대본으로 들어오는 외길.** `entry_need(sc)` 가 들어오는 길이 하나뿐인 동안 거슬러 올라가며 그 길의 스위치 가지와 선택지 잠금을 모은다(`up`). 「엽운상 무림대회 동행」은 `S0603_02` 가 조건 없이 세우지만 그 대본은 `S0603_01` 의 「엽운상 공략 중 == 1」 가지로만 온다. 제자리로 돌아오는 대화 메뉴(`S0603_02` → `S0603_02`)는 들어오는 길로 세지 않는다. 미션이 직접 여는 대본에서는 멈춘다 — 그쪽은 `mission_gate` 가 본다.

**좁힌 것 셋.**

- **장면 안에서만 뜻이 있는 값은 조건으로 안 싣는다.** 선택지 잠금의 절반 이상이 `Talk_Option_NN == 0`(이미 물어본 질문인가) 같은 것이다. `A0` · `B0` · `C0` · `TC` 로 시작하는 플래그와 **지금 세우는 그 플래그 자신**에 대한 비교는 버린다. 버리지 않으면 「공동파에 사람 파견」(M70025 = 1)이 「M70025 == 0 이어야 한다」를 전제로 갖게 된다.
- **이름 없는 조건으로 잠긴 자리는 `optDead`.** 게임 데이터에 없는 조건(`XXX` 등)은 늘 거짓이다. `build_site` 의 `DEAD_SET` · `UNSAT` 과 `save_read.make_reachable` 이 `misDead` 와 똑같이 그 자리를 건너뛴다. 리더의 갈래 목록은 그런 값을 「이 빌드에서는 고를 수 없다」로 적는다(회의의 「무림맹에 호응」).
- **다른 스크립트는 건드리지 않는다.** `enclosing()` 은 `mk_story` · `mk_presence` · `mk_cast` · `mk_affect` 도 쓴다. `gates` 는 기본이 꺼져 있어 그쪽 출력은 그대로다. (그쪽은 선택지 가지 안의 줄을 여전히 조건 없는 줄로 본다 — `mk_cast` 가 잠긴 선택지 안에만 나오는 사람을 `sure` 로 셀 수 있다. 확인하지 않았다.)

**이름 없는 플래그를 읽는 정규식도 고쳤다.** `M30026 (설명)` 꼴에서 아이디를 뽑던 `[A-Z]\d{4,6}` 가 `S2503_Break_01_001` 을 `S2503` 으로 잘라 읽고 있었다. 뒤가 공백이거나 끝일 때만 받는다(`RE_BAREID`).

### 경로 조건으로 올리기 (`build_site.gate_conds`)

경로가 요구하는 값이 **그 장면 안에서 서는 임시 플래그**(`A0…`)이고 그 값을 세우는 자리의 잠금이 하나로 정해지면, 그 잠금을 경로 조건(`flags` · `req`)으로 올린다. 잠금이 요구하는 플래그를 세우는 자리가 전부 같은 「○○ 공략 중 == 1」을 전제로 하면 그것도 싣는다. 풍운사 20 이 손으로 적은 것 없이 같은 조건이 된다 — `[엽운상 무림대회 동행] == 1` · `[위국 공략 중] == 0` · `[엽운상 공략 중] == 1`.

같은 장면에서 서는 값만 본다. 앞 장면에서 세운 임시 플래그를 읽는 경로(생사부 99 의 `임시 플래그 2 == 1` 은 `ch2_6_2_3` 이 세우고 `ch2_6_3_1` 이 읽는다)는 손대지 않는다 — 그 조건은 들어오는 길의 스위치 · 주사위로 이미 경로에 실려 있다.

## 하후란을 놓친 회차도 닫는다 (`save_read.route_closed`, 2026-10-02)

## 엽운상 루트는 청성행 회차 전용이다 (2026-10-02)

위 「엽운상 루트는 열려 있고…」 절의 **좁힌 것**(잔류인데 청성행을 안 탄 회차는 막지 않았다)을 풀었다. 그 회차도 못 탄다.

엽운주는 `ch2_4_10_3`(2년 8월)에서 빠지지만 그 대본이 `Mission("Main", "M2010_03")` 을 걸고, `M2010_03`(`ch2_6_1`)의 모든 가지가 `M2010_04` = `ch2_8_2`(2년 10월 중순, 조건 없음)로 이어져 그를 되돌려 놓는다. 그 뒤 3년 1월까지 엽운주를 내보내는 자리는 청성 라인뿐이다. 그래서 `S0204_01` 은 그대로 뜨고, 「유학 선택 == 1」이 아니면 남매가 떠난다.

`build_site` 는 `notBranch = {study: 2}` 대신 **`qc = '1'`** 을 싣는다(경로가 `S0208_*` 이거나 `[엽운상 공략 중] == 1` 을 요구할 때). 열두 항목의 경로가 바뀌었고, 공동파 세이브에서는 판정이 그대로 「불가」이며 사유 문장만 달라졌다. **잔류 세이브가 없어 플레이로는 확인하지 못했다** — 근거는 대본뿐이다. 공동파 쪽은 작성자의 세이브로 확인됐다(`--story S0204_01`: `_03` → `_03_01` → `_01_01`, 그 뒤 E12000 · E12100 = 0).

## 고칠 때 — 줄바꿈을 지킨다

`도구/*.py` 는 CRLF 다. 파이썬으로 읽어 고쳐 쓸 때 `open(…, newline='')` 을 빼먹으면 파일 전체가 LF 로 바뀌어 `git diff` 가 통째로 잡힌다(2026-10-02 에 세 파일을 그렇게 만들었다가 되돌렸다). 고친 뒤 `git diff --stat` 의 줄 수가 고친 만큼인지 본다.

## 구간 미션의 「마지막 기회」는 끝으로 잰다 (2026-10-02)

`flagWhen[플래그].set[값].max` 가 그 값을 세우는 미션의 **시작** 시점이었다(`known_wk` 하나만 썼다). 구간(區間) 미션은 끝이 따로 있어서, 「세울 수 있는 마지막 시점이 지났다」가 너무 일찍 나올 수 있었다. 이제 `known_last`(정의의 시점들 중 가장 늦은 것)를 끝으로 싣는다.

같은 자리에서 `save_read.missed_flags` 가 한국어 이름 없는 플래그(조건문에 아이디 그대로 적힌 것)를 통째로 건너뛰고 있었다. 한청서 23 을 여는 `Talk_Girl_05_02_001` 은 `S2402_01`(공동파 유학 2년차 구간 미션) 하나만 세우는데, 이름표가 없어 3년차 세이브에서도 「아직」으로 남았다. 작성자가 「설산행 이벤트냐」고 물어 드러났다 — 장면 요약도 「설산 숲」으로 잘못 적혀 있었다(`scene_ko.py`, 탈백 숲으로 고침). 세이브 20 개에서 바뀐 것은 한청서 23 이 「가능 → 불가」가 된 것뿐이다.

## 요구는 「모든 길에 걸린 것」만 (2026-10-05)

들어오는 길이 여럿이면 길마다 스위치가 다르다. 그것을 전부 모아 요구로 실으면 없는 조건이 생긴다 — 생#96 을 「엽운상 호감도 30 미만 필요, 불가」로 띄웠고 작성자는 그 전투를 이기고 지나갔다. 생#103 의 「처세 40 미만」은 `luaparse` 가 다시 쓰인 변수 이름을 잘못 풀어 생긴 것이었고, 작성자는 처세를 65 에서 35 로 내렸다.

- `luaparse.parse` 는 `if` 줄에서 그때의 체크포인트를 굳힌다(`resolved`). 같은 `switch_NNN_result` 를 가지 안에서 다시 선언하는 대본이 35개 있다.
- `build_site.need_of(script)` 가 필수 스위치 가지를 뽑는다. 거른 것은 `pathReqs`.
- 꺼진 미션(`active: false`)은 `build_site` 시작에서 뺀다.
- `python audit_need.py > audit.txt` — 미획득 전체를 다시 점검한다. 「의심」에 뜨는 것은 `data.json` 의 요구가 필수 조건에 안 보이는 것이다. 지금은 생#104 하나(선택지 잠금이라 진짜).
- 스위치 가지 번호가 조건 개수보다 크면 **전부 아님**이다. 조건 문장을 그대로 읽으면 뒤집힌다(생#102 를 그렇게 한 번 잘못 읽었다).
- **리더가 「모자람 · 불가」라 해도, 작성자에게 「못 딴다 · 질 필요 없다 · 수치를 맞춰라」고 말하기 전에 그 장면 대본을 직접 읽는다.**

## 순서표가 있는 항목은 순서표가 등급을 정한다 (2026-10-07)

`save_read.RECIPES` 에 생#99(`recipe_sheng99`) · 생#102(`recipe_sheng102`)를 더했다. 생#99 는 조건이 `임시 플래그 2 == 1` 하나로 보이는데 그 값은 앞 장면 `ch2_6_2_3` 에서만 서고, 거기 닿는 길의 수치(수양 41 이상 · 성정 79 이하 · 도덕 40 이상 · 주사위 1~50 + 구력 70 이상)가 진짜 조건이다. 자동 추출은 임시 플래그를 버리고 그 수치를 「길에 따라 다름(조건 아님)」으로 내려 「확실 · 수치 조건 없음」이라 했다. 순서표는 대본을 읽고 손으로 쓴 단계라 그쪽을 믿는다 — `recipe_tier` 가 단계 중 ✗ 가 있으면 「모자람」, 아직인 것이 있으면 「대기」, 다 됐으면 「확실」로 등급을 덮는다(한#24 는 예전 동작 그대로 둔다).

### 일반 해법 — 임시 플래그를 앞 장면이 세우는 경우 (`build_site.via_setter`, 2026-10-07)

항목 장면의 반드시 거치는 조건에 `[임시 플래그 N] == v`(v ≠ 0)가 있고, 그 값을 `SetFlag` 로 세우는 대본이 **그 장면의 조상** 중에 있으면, `need_via` 가 「세우는 장면을 거쳐 항목 장면에 닿는 길」만 놓고 모든 길에 걸린 걸음을 다시 센다. `need_of` 와 같은 방식(걸음 하나를 빼 보고 그래도 닿는지)이고 출발점만 다르다. 결과로:

- 그 길에 걸린 스위치 조건이 `reqs` 에 실린다(생#99: 수양 40 초과 · 도덕 40 이상 · 성정 80 미만).
- 반드시 고르는 선택지와 넘겨야 하는 주사위가 `o['via']` 에 실린다. 리더는 「앞 장면 … 을 거쳐야 조건이 선다」 줄로, 웹은 경로 상자의 「반드시 거치는 앞 장면」으로 보여 준다.
- 그 장면을 안 거치는 길의 조건은 `pathReqs`(길에 따라 다름)로도 싣지 않는다. 대안이 아니라 틀린 길이다.

**좁혀 둔 곳.** 같은 장면 안에서 서는 값은 건드리지 않는다(`temp_flag_why` 가 맡는다). 그 플래그를 `AddFlag` 로 더하는 대본이 조상에 있으면 손대지 않는다(값을 못 가린다). 대본 밖(전투)에서 서는 값은 세우는 장면을 못 찾으니 그대로다. 넣기 전후로 `data.json` 을 견줬다 — 바뀐 경로는 둘(생#99, 이미 딴 생#4)이고 판정이 바뀐 항목은 없다.
